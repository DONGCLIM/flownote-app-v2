# FlowNote 서버 작업 (Cloud Functions)

양재 화훼공판장 경매 시세를 **하루 한 번** 요약해 Firestore에 저장한다.

## 왜 서버가 필요한가

`지난주보다 41% 올랐어요`는 **최근 6번의 경매 결과**가 있어야 계산된다.
오늘 시세는 오늘 경매가 끝나야 나오므로 앱에 미리 넣어둘 수 없다.

| | 호출 주체 | 빈도 | 앱이 받는 크기 |
|---|---|---|---|
| ❌ | 앱 | 영수증 열 때마다 | 185 KB × 매번 |
| ✅ | **서버 1대** | **하루 1번** | **약 6 KB** |

앱은 경매 API를 **직접 부르지 않는다**. Firestore 요약 문서 하나만 읽는다.
영수증을 100장 찍어도 추가 통신은 0이다.

## 배포

```bash
# 1) 서비스키를 Secret Manager에 넣는다 (소스에 박지 않는다)
firebase functions:secrets:set FLOWER_API_KEY

# 2) 의존성 설치 후 배포
cd functions && npm install
firebase deploy --only functions

# 3) 첫 데이터를 즉시 채운다 (스케줄을 기다리지 않고)
curl "https://asia-northeast3-<PROJECT_ID>.cloudfunctions.net/updateFlowerPricesNow"
```

`firestore.rules`도 함께 배포해야 앱이 읽을 수 있다:
```bash
firebase deploy --only firestore:rules
```

## 함수

| 이름 | 종류 | 설명 |
|---|---|---|
| `updateFlowerPrices` | 스케줄 | 매일 17:30 KST. 요약을 `market/yangjae_latest`에 쓴다 |
| `updateFlowerPricesNow` | HTTP | 수동 실행 (배포 직후 채우기 / 점검용) |

시각을 17:30으로 잡은 이유: 경매는 새벽~오전에 끝나고 정산 데이터가 낮에 올라온다.

## 실측 근거 (2년치 337,383행)

1. **경매는 월·수·금만 열린다.** 화/목/토는 행이 20개 남짓.
   → `어제 대비`가 아니라 `최근 3경매일 vs 이전 3경매일`. 3경매일 ≈ 1주.

2. **요약이 묵으면 판정이 빨리 틀린다.**
   | 묵은 정도 | 오름/내림 판정 불일치 |
   |---|---|
   | 1경매일(2일) | 29% |
   | 2경매일(4일) | 46% |
   | 3경매일(7일) | 56% |

   → 하루 1번 갱신이 **필수**. 주 3회로 줄이면 절반이 거짓이 된다.

3. **단기 추세에 예측력은 없다.** 오름 판정 후 다음 기간에도 같은 방향일
   확률 51~53% = 동전 던지기 (문턱 5~25% 전부 동일).
   → 앱은 `올랐어요`(사실)만 쓰고 `오를 것 같아요`(예측)는 절대 쓰지 않는다.

4. **등급 구성비 오염은 무시 가능.** 등급 고정 가중 지수와 비교해
   방향 불일치 1~11%, 평균 차이 0.7~5.1%p → 단순 가중평균으로 충분.

5. **이 API는 양재 단독이다.** 응답에 시장 구분 필드가 없어 직접 대조했다.
   사이트 메인 "양재 거래동향" 집계와 **물량 오차 0단**으로 일치:
   | 날짜 | API | 사이트 |
   |---|---|---|
   | 2026-08-21 | 96,033단 | 96,033단 |
   | 2026-08-20 | 1,056단 | 1,056단 |
   | 2026-08-22 | 1,097단 | 1,097단 |

   → 앱에 `양재 경매가`라고 표기해도 사실이다.

6. **단위는 `단`.** 사이트가 스스로 `단(속)`으로 표기 → 1속 = 1단.
   송이 환산은 하지 않는다 (품목마다 다르고 검증한 값이 아니다).

## 요약 문서 형태

`market/yangjae_latest`
```json
{
  "v": 1, "market": "양재", "unit": "단",
  "base": "2026-08-21", "window": 3, "maxStale": 3,
  "itemCount": 129,
  "items": {
    "장미": { "d": "2026-08-21", "p": 11827, "c": 41 },
    "국화": { "d": "2026-08-21", "p": 3476,  "c": -12 },
    "튜립": { "d": "2026-08-21", "p": 19027, "c": null }
  }
}
```
- `d` 그 시세가 찍힌 경매일 · `p` 원/단 · `c` 지난주 대비 % (계산 불가면 `null`)
- 키를 한 글자로 줄인 이유: 247품목 × 3필드라서 이름을 길게 쓰면 문서가 몇 배 커진다.
