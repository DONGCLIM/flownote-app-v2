# 보안 규칙 테스트

> 🔴 **규칙을 바꾸면 배포 전에 반드시 이것을 돌린다.** 하나라도 실패하면
> 배포하지 않는다. (#194 사고 — 컴파일만 확인하고 올렸다가 회원 영수증
> 저장이 막혔다. 컴파일 성공은 "문법이 맞다" 일 뿐, "회원이 저장할 수
> 있다" 는 확인이 아니다.)

## 돌리는 법

```bash
cd rules_test
npm install          # 처음 한 번
npm test             # 에뮬레이터를 켜고 규칙 테스트를 돌린다
```

Java 가 있어야 한다(에뮬레이터가 JVM 위에서 돈다). `java -version` 으로
확인한다.

## 무엇을 보나

저장소의 `../firestore.rules` · `../storage.rules` 를 **그대로** 읽어서,
진짜 회원이 하는 일이 되는지 확인한다.

| 누구 | 무엇 |
|---|---|
| 구글 회원 | 영수증 저장 · 사진 업로드 · 학습 데이터 · 학습 이미지 · 문의 · 사입 리스트 |
| 카카오 회원 | 위와 같음 (커스텀 토큰이라 토큰 모양이 다르다 — 이게 #194 의 핵심) |
| 회원 A → B | 남의 데이터는 읽기도 쓰기도 **안 된다** |
| 게스트(익명) | 자기 `users/{uid}` 아래만. 공용 경로는 앱에서 안 간다 |

## 🔴 카카오를 꼭 같이 보는 이유

카카오 로그인은 Firebase 기본 제공자가 아니라 서버 함수가 발급한
**커스텀 토큰**이다. 그래서 토큰 안이 구글·이메일과 다르다.

```
구글   firebase.sign_in_provider = 'google.com'
카카오 firebase.sign_in_provider = 'custom'      ← 다르다
익명   firebase.sign_in_provider = 'anonymous'
```

#194 에서 `sign_in_provider` 를 직접 꺼내 쓰는 규칙을 올렸다가 사고가
났다. 구글만 테스트했으면 못 잡는다. **세 가지를 모두 돌려야 한다.**
