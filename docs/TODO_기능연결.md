# 나중에 연결할 기능 목록

이 문서는 **화면만 먼저 만들고 기능은 나중에** 붙이기로 한 것들을 적어 둔다.
사장님 지시: "데이터는 예시값으로 채우고, 실제 기능(데이터 불러오기·계산 등)은
만들지 마. 나중에 연결할 기능은 이 파일에 화면별로 목록으로 적어줘."

## 읽는 법

| 표시 | 뜻 |
|---|---|
| 🔴 | 이게 없으면 화면이 거짓말을 한다. 가장 먼저 붙여야 한다. |
| 🟡 | 없어도 화면은 말이 되지만, 기능으로서는 반쪽이다. |
| ⚪ | 있으면 좋은 것. 나중으로 미뤄도 된다. |

**지금 화면에 보이는 숫자는 전부 손으로 적어 넣은 예시값이다.**
실제 영수증·시세와 아무 상관이 없다. 사장님께 보여드릴 때
"이 숫자는 아직 예시"라고 말씀드려야 한다.

---

## 🟠 나중에 결정할 것 (기능 작업 시작 전에 먼저 여쭌다)

사장님 지시: "지금 정하지 않을게. 그대로 둬. 나중에 기능 작업 시작할 때
이 섹션부터 먼저 나한테 물어봐줘."

**기능을 붙이기 전에 아래를 하나씩 여쭙고, 답을 받은 뒤에 작업을 시작한다.**
여쭙지 않고 내 판단으로 정하지 않는다. 지금까지 이런 걸 멋대로 정해서
두 번 고친 적이 있다.

### 시즌 매입 비교 (`GuideSeasonDsScreen`)

| | 물어볼 것 | 지금 상태 |
|---|---|---|
| ① | 시작/종료 월과 비교 기준(전년 동기·올해 월평균)을 **눌러도 숫자가 안 바뀌는 것**을 그대로 둘까요, 실제로 다시 계산할까요? | 눌리면 칠해지기만 한다. 일부러 그렇게 뒀다 — 안 눌리면 고장으로 보이고, 숫자까지 바뀌면 거짓말이 된다 |
| ② | **품목군 4분류**(절화 / 부자재 / 화분·식물 / 기타)를 영수증 품목에서 어떤 기준으로 나눌까요? | 앱에 이 분류가 아예 없다. 이걸 정하지 않으면 `품목군별 증감` 카드를 만들 수 없다 |
| ③ | 매입이 **줄었을 때** `전년 대비` 배지 색을 코랄 말고 다른 색으로 바꿀까요? | 늘든 줄든 코랄이다. 매입이 주는 게 꼭 나쁜 일은 아니다 |

### 스마트 사입 가이드 (`GuideDsScreen`)

| | 물어볼 것 | 지금 상태 |
|---|---|---|
| ④ | **저장된 사입 리스트** 화면을 만들까요? | 누르면 "곧 준비해서 알려드릴게요." 안내만 뜬다 |
| ⑤ | **사입 메모장** 화면을 만들까요? 만든다면 **부케 스케치**를 손그림으로 그릴까요, 사진을 붙일까요? | 위와 같다. 스케치 방식이 안 정해져 설계를 못 한다 |
| ⑥ | **사입 한도(40만원)** 를 사장님이 직접 정하는 칸을 어디에 둘까요? (프로필 설정 / 가이드 화면 안 / 예산 검토 화면) | 코드에 40만원이 박혀 있다 |
| ⑦ | **금액 표기**를 `27.4만원` 으로 둘까요, `274,000원`(`FnDs.won()`)으로 통일할까요? | 화면마다 다르다. 가이드는 `만원`, 다른 화면은 `원` |

### 원가 계산기 (`GuideCostDsScreen`)

| | 물어볼 것 | 지금 상태 |
|---|---|---|
| ⑧ | **상품 구성(웨딩 부케·기념 화환·센터피스·작은 꽃집)** 을 사장님이 직접 만들고 지울 수 있어야 할까요? | 네 가지가 코드에 박혀 있다 |
| ⑨ | **로스율 기본값 8%** 와 **판매 배수 기본값 ×2.5** 를 사장님이 바꿔서 저장할 수 있어야 할까요? | 예시값으로 박혀 있다 |
| ⑩ | 계산한 레시피를 **저장**할까요? 저장한다면 기기에만 둘까요, 계정에 묶을까요? | 저장 기능이 없다. 화면을 나가면 사라진다 |

## 스마트 사입 가이드 (`lib/screens/ds/insight_ds_screens.dart` · `GuideDsScreen`)

예시값이 박혀 있는 곳: `GuideDsScreen.budgetSpend` / `budgetPlan` / `budgetCap` /
`budgetLeft` / `budgetRatio`, 그리고 `GuideDsScreen._menu` 의 `left` · `right`.

### 맨 위 "이번 주 사입 준비" 카드

- 🔴 **예상 예산 금액** (`27.4만원`) — 저장된 사입 리스트의 품목 × 직전 매입 단가를
  더해서 낸다. 지금은 글자다.
- 🔴 **한도 금액** (`400,000원`) — 사장님이 직접 정하는 값. 설정에 저장할 칸이 필요하다.
  한도를 정한 적이 없으면 이 카드를 통째로 감출지, "한도를 정해 주세요"를 보여줄지
  **정해야 한다.**
- 🔴 **막대 채움 비율** (`budgetRatio`) — 예상 예산 ÷ 한도. 지금은 0.685 고정.
  한도를 넘으면 어떻게 보일지(막대를 빨갛게? 100% 에서 멈춤?) **정해야 한다.**
- 🔴 **남은 금액** (`12.6만원`) — 한도 − 예상 예산. 음수가 되면 "N만원 넘었어요"로
  문구가 바뀌어야 한다.
- 🟡 **사입 예정일·품목 수** (`금요일 사입 예정 · 3개 품목`) — 저장된 사입 리스트에서.
  예정일이 없으면 무엇을 보여줄지 정해야 한다.
- ⚪ 금액 표기를 `FnDs.won()` 으로 통일. 지금 화면은 `27.4만원` 처럼 줄여 쓰는데,
  `FnDs.won()` 은 `274,000원` 을 낸다. **둘 중 무엇으로 할지 정해야 한다.**

### 목록 카드 아래 줄 숫자

- 🔴 **시즌 매입 비교** `1~7월 +7.5%` — 올해 누적 매입 대 전년 같은 기간. 영수증에서.
- 🔴 **원가 계산기** `권장가 307,200원` / `마진 60%` — 마지막으로 계산한 레시피를
  저장해 두고 그 값을 보여준다. 저장한 적이 없으면 무엇을 보여줄지 정해야 한다.
- 🔴 **예산 검토** `한도 40만원 중 27.4만원` / `69% 사용` — 위 카드와 같은 값.
  한 군데서 계산해서 두 곳이 같이 쓰게 해야 한다. 따로 계산하면 서로 어긋난다.
- 🟡 **저장된 사입 리스트** `3건 저장 · 1회 평균 13.8만원` / `최근 07.24`
- 🟡 **사입 메모장** `마지막 기록 07.24` / `메모 2줄`

### 아직 화면이 없는 메뉴

- 🔴 **저장된 사입 리스트** — 누르면 "곧 준비해서 알려드릴게요." 안내만 뜬다.
  (`GuideDsScreen._open` 의 `saved`)
- 🔴 **사입 메모장** — 위와 같다. (`memo`) 부케 스케치를 어떻게 그리고 저장할지
  **정해야 한다** (손그림? 사진 첨부?).

### 저장

- 🔴 사입 리스트·메모를 **어디에 저장할지** 정해야 한다.
  기기 안에만 둘지(`SharedPreferences`), 계정에 묶어 Firestore 에 둘지.
  기기 안에만 두면 폰을 바꿀 때 사라진다.

## 시즌 매입 비교 (`lib/screens/ds/insight_ds_screens.dart` · `GuideSeasonDsScreen`)

예시값이 박혀 있는 곳: `GuideSeasonDsScreen.total` / `prevTotal` / `diffPct` /
`diffAmount` / `rangeLabel` / `bars` / `heat` / `trendNow` / `trendPrev` / `items`.

### 기간 고르기

- 🔴 **시작 월 · 종료 월** — 지금은 고르면 글자만 바뀌고 숫자는 그대로다.
  고른 기간으로 영수증을 다시 더해야 한다.
- 🔴 **비교 기준** (`전년 동기` / `올해 월평균`) — 누르면 칠해지기만 한다.
  기준을 바꾸면 아래 모든 숫자와 `전년 동기` 라벨이 함께 바뀌어야 한다.
- 🟡 시작 월이 종료 월보다 뒤일 때 어떻게 할지 **정해야 한다**
  (못 고르게 막을지, 자동으로 뒤집을지).
- ⚪ 해(연도)는 아직 못 고른다. 2026 으로 고정돼 있다.

### 숫자

- 🔴 **선택 기간 매입** (`27,890,000원`) — 고른 기간의 영수증 합계.
- 🔴 **전년 대비 배지** (`전년 대비 +7.5%`) — 줄었을 때 색을 바꿀지 **정해야 한다**.
  지금은 늘든 줄든 코랄이다. 매입이 주는 건 나쁜 일이 아닐 수도 있다.
- 🔴 **전년 동기 합계** (`25,940,000원`) · **증감** (`+1,950,000원`)
- 🔴 **기간 비교 막대** (`bars`) — (달, 올해, 전년) 7쌍. 기간을 바꾸면 개수도 바뀐다.
- 🔴 **월별 매입 추이** (`trendNow` / `trendPrev`) — 막대와 같은 값을 쓴다.
  한 군데서 만들어 두 카드가 같이 쓰게 해야 한다. 따로 계산하면 어긋난다.
- 🔴 **품목군별 증감** (`items`) — 절화/부자재/화분·식물/기타. 영수증 품목을
  네 갈래로 나누는 **분류 기준을 정해야 한다.** 지금 앱에 그 분류가 없다.
- 🟡 **성수기 지도** (`heat`) — 달마다 매입액을 0~1 로 환산해 진하기로 쓴다.
- 🟡 **데이터 분석 문장** — 지금은 통째로 고정 문장이다. 숫자가 붙으면
  문장도 숫자에 따라 만들어져야 한다. 증가/감소에 따라 말이 바뀌어야 한다.

### 빈 경우

- 🔴 영수증이 없거나 전년 자료가 없을 때 무엇을 보여줄지 **정해야 한다.**
  지금은 어떤 경우에도 예시 숫자가 보인다 — 실제로는 이게 가장 위험하다.

## 이미 있던 하위 화면 (이번에 건드리지 않음)

`GuideSeasonDsScreen` · `GuideCostDsScreen` · `GuideBudgetDsScreen` 은
예전부터 있던 화면이고, 이번 작업에서 손대지 않았다.
이 화면들도 예시 데이터로 그려져 있으니 나중에 같이 살펴봐야 한다.
