# 게스트 차단 규칙 — 재설계안 (배포 안 함 · 사장님 확인 대기)

> 🔴 **이 문서는 제안일 뿐입니다. `firestore.rules`·`storage.rules` 에는
> 아무것도 반영하지 않았습니다.** 두 파일은 지금 `520662e`(11/25 저녁,
> 콘솔에 올라가 있는 버전) 와 **완전히 같습니다.**
> 사장님이 "좋다" 하시기 전에는 배포하지 않습니다.

---

## 1. 무엇이 회원 영수증 저장을 막았나

### 실제로 라이브에 올라간 것은 `e92c041` 하나다

| 커밋 | 규칙 배포 | 비고 |
|---|---|---|
| `0d33d2d` | ❌ | 커밋만 |
| **`e92c041`** | ✅ **배포됨** | 이것이 사고를 냈다 |
| `ca8d4a0` | ❌ | `--dry-run` 만 돌렸다 |

### 범인 — 모든 스캔이 지나는 두 줄을 `isMember()` 로 조였다

```
storage.rules
-  match /receipts/{allPaths=**} {
-      allow write: if isSignedIn()          ← 회원 스캔이 매번 지나는 길
+      allow write: if isMember()

firestore.rules
-  match /training_data/{docId} {
-      allow create: if isSignedIn();        ← 회원 스캔이 매번 지나는 길
+      allow create: if isMember();
```

이 두 경로는 **게스트 전용이 아니다.** `training_data_service.saveInitialScan()`
이 영수증을 찍을 때마다 부른다 — 회원이든 아니든 **모든 스캔**이 지난다.
게스트를 막으려고 건드렸는데, 실제로는 **회원이 쓰던 길에 새 조건을 끼워 넣은
것**이다.

### 왜 회원까지 막혔나 — `isAnon()` 이 터지면 전체가 거부된다

```
function isAnon() {
  return isSignedIn()
         && request.auth.token.firebase.sign_in_provider == 'anonymous';
}
```

보안 규칙에서 **없는 키를 `.` 로 꺼내면 식이 오류**가 되고, 오류가 난 규칙은
`allow` 가 아니라 **거부**로 끝난다. 카카오 로그인은 커스텀 토큰이라 토큰 모양이
구글·이메일과 다르고(`provider: 'kakao'` 같은 우리 클레임이 들어간다),
`firebase.sign_in_provider` 를 그대로 꺼내는 순간 판정이 어긋날 수 있다.
`isMember()` 가 `isAnon()` 에 기대고 있어서, **`isAnon()` 이 한 번 어긋나면
회원도 통째로 막힌다.**

### 세 줄 요약

1. **`storage.rules` 의 `receipts/**` write** 를 `isSignedIn()` → `isMember()` 로
   바꾼 줄. 여기는 게스트 전용이 아니라 **회원 스캔이 매번 쓰는 학습 업로드
   경로**였다.
2. **`firestore.rules` 의 `training_data` create/update** 를 같은 식으로 바꾼 줄.
   역시 모든 스캔이 지난다.
3. 두 줄이 기대는 `isAnon()` 이 `request.auth.token.firebase.sign_in_provider`
   를 **직접** 꺼내는데, 이 값이 없거나 토큰 모양이 다르면(카카오 커스텀 토큰)
   식이 오류로 끝나 **회원까지 거부**된다.

### 내가 놓친 것 (같은 실수를 막기 위해)

- `isMember()` 를 **기존 회원 경로**에 끼워 넣었다. 게스트를 막는다면서
  회원이 쓰던 조건을 **고쳤다.** 새 조건은 새 경로에만 붙였어야 한다.
- 규칙을 **컴파일만** 확인하고 배포했다. 컴파일은 문법만 본다.
  "회원이 영수증을 저장할 수 있나" 는 한 번도 확인하지 않았다.
- 익명 로그인이 **꺼져 있는 상태**에서 익명 차단 규칙을 올렸다. 막을 대상이
  없는데 위험만 올린 셈이다.

## 2. 재설계 원칙 — 회원 흐름을 건드리지 않는다

| 원칙 | 왜 |
|---|---|
| **기존 `allow` 줄을 고치지 않는다.** 오직 덧붙이기만 한다 | 회원이 쓰던 길의 조건을 바꾸는 순간 회원이 위험해진다 |
| 클레임은 **`.get()` 으로 기본값과 함께** 꺼낸다 | 키가 없어도 오류가 안 난다. 오류 = 거부다 |
| 판정이 흔들리면 **회원 쪽으로 기운다** | 게스트를 한 명 놓치는 것보다 회원이 막히는 게 훨씬 나쁘다 |
| 게스트는 **자기 `users/{uid}` 아래만** | 공용 컬렉션은 아예 손대지 않는다 |
| 익명 로그인을 **켜기 전까지는 올리지 않는다** | 막을 대상이 없는데 위험만 생긴다 |

### 바뀌는 헬퍼 — 오류가 안 나는 꺼내기

```
// 🔴 `request.auth.token.firebase.sign_in_provider` 를 **직접 꺼내지 않는다.**
//    없는 키를 `.` 로 꺼내면 식이 오류가 되고, 오류 난 규칙은 거부로 끝난다.
//    카카오는 커스텀 토큰이라 토큰 모양이 달라서 실제로 이 사고가 났다(#194).
//    `.get()` 은 키가 없으면 기본값을 준다. 절대 터지지 않는다.
function signInProvider() {
  return request.auth.token.get('firebase', {}).get('sign_in_provider', '');
}

// 🔴 "익명이라고 **확실히** 말할 수 있을 때만" true.
//    모르겠으면 false — 즉 회원으로 본다. 판정이 흔들리면 회원 쪽으로.
function isAnon() {
  return isSignedIn() && signInProvider() == 'anonymous';
}
```

### 경로별로 어떻게 할지

| 경로 | 지금(콘솔) | 제안 | 회원 영향 |
|---|---|---|---|
| storage `receipts/**` | `isSignedIn()` | **그대로 둔다** | 없음 |
| storage `training_data/**` | `isSignedIn()` | **그대로 둔다** | 없음 |
| storage `users/{uid}/**` | 주인만 | **그대로 둔다** | 없음 |
| storage `inquiries/{uid}/**` | 주인만 | **그대로 둔다** | 없음 |
| firestore `training_data` | `isSignedIn()` | **그대로 둔다** | 없음 |
| firestore `inquiries` create | `isSignedIn()` | **그대로 둔다** | 없음 |
| firestore `market` read | `isSignedIn()` | **그대로 둔다** | 없음 |
| firestore `users/{uid}/**` | 주인만 | **그대로 둔다** | 없음 |
| firestore `users/{uid}/usage/**` | (없음) | **새로 추가** | 없음 (새 경로) |

**즉 이번 제안에서 기존 줄은 단 한 줄도 바꾸지 않는다.**
`users/{uid}/usage/{docId}` 라는 **새 경로 하나만** 더한다.

```
// ── 게스트 체험 사용 횟수 (새 경로 — 기존 회원 흐름과 겹치지 않는다)
//
//   users/{uid}/usage/counters  { scans: 0 }
//
//   🔴 위의 `users/{uid}/{document=**}` 포괄 규칙으로도 이미 통과한다.
//      여기서 더하는 것은 **게스트에게만 거는 상한**이다. 회원은
//      `isOwner(uid)` 한 줄로 전부 통과하므로 아무것도 달라지지 않는다.
match /usage/{docId} {
  allow read, delete: if isOwner(uid);

  // 회원은 조건 없이 통과한다 — 제일 먼저 본다.
  allow create, update: if isOwner(uid) && !isAnon();

  // 게스트만 1씩·5까지.
  allow create: if isOwner(uid) && isAnon()
                && request.resource.data.scans is int
                && request.resource.data.scans >= 0
                && request.resource.data.scans <= 1;

  allow update: if isOwner(uid) && isAnon()
                && request.resource.data.scans is int
                && request.resource.data.scans <= 5
                && request.resource.data.scans >= resource.data.scans
                && request.resource.data.scans <= resource.data.scans + 1;
}
```

### 그럼 게스트는 공용 컬렉션에 못 쓰게 어떻게 막나

공용 쪽(`training_data`, `inquiries`, 최상위 `receipts/`)은 **규칙을 건드리지
않고 앱에서 막는다.** 게스트일 때 아예 부르지 않게 한다.

- `training_data_service.saveInitialScan()` — 맨 앞에서 게스트면 바로 돌아간다
- `inquiry_service` — 프로필에서 🔒 로 막는다(④단계)

규칙으로도 막고 싶으시면, **익명 로그인을 켜신 다음** 위 `signInProvider()`
방식으로 한 경로씩, 배포 전에 아래 확인을 거쳐 올리는 것을 권합니다.

### 배포 전 확인 절차 (이번에 없어서 사고가 났다)

1. 익명 로그인을 **켠 뒤** `firebase emulators:start` 로 규칙 테스트를 쓴다
   (구글 회원·카카오 회원·익명 세 가지로 **영수증 저장**을 돌려 본다)
2. 콘솔 **규칙 시뮬레이터**로 `users/<회원uid>/receipts/x.jpg` 쓰기가
   통과하는지 눈으로 본다
3. 그 다음에 배포한다. **컴파일 성공은 확인이 아니다.**
