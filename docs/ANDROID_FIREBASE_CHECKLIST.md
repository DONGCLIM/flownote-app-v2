## ✅ 작업 2-B — SHA-1 지문 추가 (완료됨, 기록용)

### 왜 또 해야 하나요?

받은 파일을 검증해보니 **앱 등록은 성공**했지만 **SHA-1 지문이 빠져** 있었습니다.

```
com.flownote.app  →  앱ID = 1:250664220370:android:38b9b61cc9c9368a6adf0b
                            ↑ 다른 앱과 다른 고유 ID = 진짜 등록됨 ✅

oauth_client = [ { "client_type": 3 } ]
                              ↑ 3 = 웹용. 구글 로그인엔 1(안드로이드)이 필요 ❌

certificate_hash 키 등장 횟수 : 0    ← 지문이 아예 없음
```

`client_type` 숫자의 뜻:

| 값 | 의미 | 구글 로그인에 필요? |
|---|---|---|
| **1** | **안드로이드 OAuth 클라이언트** | ✅ **필수** |
| 3 | 웹 OAuth 클라이언트 | ❌ 있어도 소용없음 |

**`client_type: 1` 은 SHA-1 지문을 등록해야만 파이어베이스가 자동으로 만들어 줍니다.**
지문이 없으니 1번이 안 생겼고, 그래서 구글 로그인이 아직 안 됩니다.

### 하는 방법 (2분)

1. https://console.firebase.google.com → **flownote-404ef**
2. **⚙️ → 프로젝트 설정**
3. **내 앱** 에서 **`com.flownote.app`** 카드를 클릭 (이번엔 새로 만들지 말고 기존 것!)
4. 아래로 내려가면 **`SHA 인증서 지문`** 영역이 있습니다
5. **[디지털 지문 추가]** 버튼 클릭
6. 아래 값을 붙여넣고 저장:

   ```
   796c012932f0aafb3f1dce2956739477988ef612
   ```

7. 같은 방법으로 SHA-256도 넣어두시면 좋습니다 (플레이스토어 출시 때 필요):

   ```
   a1f199f3350889b274a170a703453b7084273b0391ff2e485c2b8cc8e81098dc
   ```

8. 지문이 목록에 나타났으면 → 그 카드 위쪽의 **`google-services.json` 다운로드** 를 눌러
   **파일을 다시** 받으세요
9. **저에게 다시 주세요**

> 🔴 **반드시 지문을 넣은 "후에" 다시 다운로드하셔야 합니다.**
> 지금 갖고 계신 파일에는 지문 정보가 없습니다.

### 다시 받은 파일이 맞는지 사장님이 확인하는 법

메모장으로 열어 `certificate_hash` 를 검색하세요.

**✅ 성공**
```json
"oauth_client": [
  {
    "client_id": "250664220370-xxxxx.apps.googleusercontent.com",
    "client_type": 1,
    "android_info": {
      "package_name": "com.flownote.app",
      "certificate_hash": "796c012932f0aafb3f1dce2956739477988ef612"
    }
  },
  { "client_id": "...", "client_type": 3 }
]
```
→ `client_type: 1` 과 `certificate_hash` 가 **둘 다** 보이면 성공입니다.

**❌ 아직 안 됨**
```json
"oauth_client": [ { "client_type": 3 } ]
```
→ `certificate_hash` 가 검색되지 않으면 지문 저장이 안 됐거나, 지문 등록 전에 받은 파일입니다.

## ✅ 작업 1 — 안드로이드 앱을 **새로** 등록하기 (가장 중요)

### 왜 "새로" 인가요?

제가 이전에 잘못 안내드렸습니다. 지금 프로젝트 안에 들어있는 `google-services.json` 파일을
분석해보니 **제가 옛날에 손으로 만들어 넣은 가짜 파일**이었습니다.

증거: 파일 안에 앱이 2개 들어있는데 **둘의 고유 ID가 완전히 똑같습니다.**

```
package = com.florascan.scan   → 앱ID = 1:250664220370:android:f22c6d640864be8f6adf0b
package = com.flownote.app     → 앱ID = 1:250664220370:android:f22c6d640864be8f6adf0b
                                        ↑↑↑ 이게 똑같으면 진짜 파일일 수가 없습니다
```

파이어베이스가 진짜로 만들어준 파일이라면 앱마다 ID가 다릅니다.
즉 **`com.flownote.app` 이라는 우리 앱은 파이어베이스 콘솔에 아예 존재하지 않습니다.**

👉 그래서 "지문만 추가"가 아니라 **"앱을 처음부터 등록"** 하셔야 합니다.

### 하는 방법

1. https://console.firebase.google.com 접속
2. **flownote-404ef** 프로젝트 클릭
3. 왼쪽 위 **⚙️ 톱니바퀴 → 프로젝트 설정** 클릭
4. 화면을 아래로 내려서 **내 앱(Your apps)** 영역을 찾습니다
5. **[앱 추가]** 버튼 → **안드로이드** 아이콘(로봇 모양) 클릭
6. 아래 3개를 입력합니다:

   | 입력칸 | 넣을 값 |
   |---|---|
   | Android 패키지 이름 | `com.flownote.app` |
   | 앱 닉네임 (선택) | `FlowNote Android` |
   | **디버그 서명 인증서 SHA-1** | `796c012932f0aafb3f1dce2956739477988ef612` |

   > 🔴 **패키지 이름은 한 글자도 틀리면 안 됩니다.** 반드시 복사해서 붙여넣으세요.
   > 대문자/소문자, 점 위치까지 정확히 일치해야 합니다.
   >
   > 🔴 SHA-1 칸 이름이 "디버그"라고 적혀 있지만 **무시하고 위 값을 넣으세요.**
   > 우리는 배포용 서명키를 쓰고 있고, 파이어베이스는 이 칸에 어떤 지문이든 받습니다.

7. **[앱 등록]** 클릭

### SHA-1 지문이란?

앱이 "내가 진짜 그 앱이다"를 증명하는 지문입니다. 제가 앱에 서명할 때 쓰는
`release-key.jks` 열쇠에서 나온 값이고, 방금 다시 확인했습니다:

```
SHA1   : 79:6C:01:29:32:F0:AA:FB:3F:1D:CE:29:56:73:94:77:98:8E:F6:12
SHA256 : A1:F1:99:F3:35:08:89:B2:74:A1:70:A7:03:45:3B:70:84:27:3B:03:91:FF:2E:48:5C:2B:8C:C8:E8:10:98:DC
```

콜론(`:`) 없이 붙여쓴 형태가 위 표의 값입니다. 콜론이 있어도 파이어베이스가 알아서 처리합니다.

> 💡 SHA-256 칸도 있으면 위 SHA256 값을 같이 넣어두세요. 지금 필수는 아니지만
> 나중에 구글 플레이에 올릴 때 필요해집니다.

## ✅ 작업 2 — `google-services.json` 받아서 저에게 주기

1. 작업 1에서 **[앱 등록]** 을 누르면 바로 다음 화면에 나옵니다
2. **`google-services.json` 다운로드** 버튼 클릭
3. 그 아래 "2단계 Firebase SDK 추가", "3단계 확인" 안내는 **전부 무시하고 넘기세요**
   (그건 제가 코드로 이미 다 해놨습니다)
4. 다운로드된 파일을 **저에게 그대로 주세요**

### 파일이 제대로 왔는지 사장님이 직접 확인하는 방법 (선택)

파일을 메모장으로 열어서 `oauth_client` 를 찾아보세요.

**✅ 제대로 된 파일 (SHA-1이 등록된 상태)**
```json
"oauth_client": [
  {
    "client_id": "250664220370-xxxxxxxxxxxxx.apps.googleusercontent.com",
    "client_type": 1,
    "android_info": {
      "package_name": "com.flownote.app",
      "certificate_hash": "796c012932f0aafb3f1dce2956739477988ef612"
    }
  },
  ...
]
```

**❌ 잘못된 파일 (SHA-1을 안 넣었거나 저장이 안 된 상태)**
```json
"oauth_client": []
```

`oauth_client` 가 **빈 대괄호 `[]`** 면 구글 로그인이 안 됩니다.
그러면 작업 1로 돌아가서 SHA-1을 다시 확인하고, 파일을 **다시** 받으세요.

> 💡 파이어베이스는 SHA-1을 등록한 **후에 다시 다운로드**해야 반영된 파일이 나옵니다.
> 먼저 받아둔 파일에는 `oauth_client` 가 비어 있습니다.

## ✅ 작업 3 — Google 로그인 켜기

1. 왼쪽 메뉴 **빌드 → Authentication** 클릭
2. 상단 **Sign-in method** (로그인 방법) 탭 클릭

   | 제공업체 | 상태 |
   |---|---|
   | **이메일/비밀번호** | 이미 켜져 있어야 함 (지금 로그인 되니까) ✅ |
   | **Google** | 👉 **이걸 켜세요** |

4. **Google** 클릭 → **사용 설정(Enable)** 토글 켜기
5. **프로젝트 지원 이메일** 을 반드시 선택하세요 (안 고르면 저장 안 됩니다)
6. **저장**

## ✅ 작업 4 — Firestore 보안 규칙 붙여넣기

지금 규칙을 안 넣으면 두 가지 중 하나가 됩니다:
- **테스트 모드**로 되어 있으면 → 30일 후 모든 저장이 멈춥니다 ⏰
- **잠금 모드**로 되어 있으면 → 회원가입 정보가 아예 저장 안 됩니다 🚫

### 하는 방법

1. 왼쪽 메뉴 **빌드 → Firestore Database**
2. 데이터베이스가 없으면 **[데이터베이스 만들기]** → 위치는 **asia-northeast3 (서울)** 추천
3. 상단 **규칙(Rules)** 탭 클릭
4. 기존 내용을 **전부 지우고**, 프로젝트의 **`firestore.rules` 파일 내용을 전부 복사해서 붙여넣기**
5. **[게시]** 클릭

이 규칙이 하는 일:
- `users/{내 uid}` — **본인만** 자기 회원정보·사업자정보를 읽고 쓸 수 있음. 남의 것은 절대 접근 불가
- `users/{uid}/receipts` — 영수증 클라우드 백업 (본인만)
- `users/{uid}/consent_log` — 약관 동의 이력. **수정 불가**(법적 증빙용), 탈퇴 시에만 삭제
- `training_data` — OCR 학습 데이터. 로그인 사용자만 쓰기, **읽기는 아무도 못 함**
- 그 외 모든 경로 — **전부 차단**

## ✅ 작업 5 — Storage 보안 규칙 붙여넣기

영수증 사진을 클라우드에 올리는 기능(OCR 정확도 개선용)에 필요합니다.

1. 왼쪽 메뉴 **빌드 → Storage**
2. 시작 안 했으면 **[시작하기]** → 위치는 Firestore와 같은 곳
3. 상단 **규칙(Rules)** 탭
4. 기존 내용을 전부 지우고 프로젝트의 **`storage.rules` 파일 내용을 붙여넣기**
5. **[게시]** 클릭

> 🔴 **이번에 버그를 하나 고쳤습니다.**
> 이전 `storage.rules` 는 `training_data/` 경로만 허용했는데,
> 실제 코드는 `receipts/` 경로에 업로드하고 있었습니다.
> → 규칙을 그대로 배포했으면 **영수증 사진 업로드가 전부 거부**됐을 겁니다.
> 지금은 `receipts/` 를 허용하도록 수정했으니, **꼭 최신 파일**을 붙여넣으세요.

## 🔍 각 항목이 지금 왜 안 되는지 (기술 배경)

### "파이어베이스는 이미 연결됐는데 왜 구글 로그인만 안 돼요?"

**3가지가 서로 다른 개념**이기 때문입니다.

| 개념 | 필요한 것 | 지금 상태 |
|---|---|---|
| ① 프로젝트 연결 | `project_number` + `api_key` 만 있으면 됨 | ✅ 되어 있음 |
| ② **앱 등록** | 패키지 이름 + **SHA-1 지문** | ❌ **안 되어 있음** |
| ③ 제공업체 켜기 | 콘솔 토글 | ❌ 꺼져 있음 |

**이메일/비밀번호 로그인**은 ①만 있으면 작동합니다. 그래서 지금 회원가입·로그인이 됩니다.

**구글 로그인**은 ②와 ③이 반드시 필요합니다. 구글이 "이 지문을 가진 앱만 이 계정에
접근할 수 있다"고 확인해야 하기 때문입니다. 지문이 등록 안 됐으니 구글이 거부합니다.

### 지금 구글 버튼을 누르면 어떻게 되나요?

**앱이 죽지는 않습니다.** 제가 미리 처리해뒀습니다:

```
구글 로그인 준비가 아직 안 됐어요.
이메일로 로그인해 주세요.
```

이런 안내만 뜨고 정상 화면으로 돌아옵니다. 설정 전에도 앱은 안전하게 쓸 수 있습니다.

| 앱 추가 시 "이미 존재하는 패키지" | 이미 등록된 상태입니다. 그 앱 카드를 열어 SHA-1 만 추가하고 json 을 **다시** 받으세요 |
| 받은 json 의 `oauth_client` 가 `[]` | SHA-1 저장이 안 됐거나, SHA-1 등록 **전에** 받은 파일입니다. 등록 후 다시 받으세요 |
| Google 토글 저장이 안 됨 | **프로젝트 지원 이메일**을 선택하지 않았습니다 |
| 구글 로그인 시 `DEVELOPER_ERROR` / 코드 10 | SHA-1 이 틀렸거나 등록 안 됨. 값 재확인 |
| 구글 로그인 시 `operation-not-allowed` | 작업 3(Google 토글)을 안 켰습니다 |
| 회원가입은 되는데 정보 저장이 안 됨 | 작업 4(Firestore 규칙)를 안 했습니다 |
| 영수증 사진 업로드 실패 | 작업 5(Storage 규칙)를 안 했거나, 옛 버전 규칙을 붙여넣었습니다 |
| Firestore 가 30일 후 멈춤 | 테스트 모드였습니다. 작업 4로 정식 규칙을 게시하세요 |
